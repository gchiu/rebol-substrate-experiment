Common target: B3 convention A, all six native operations, -O2 host code.

REPRESENTATIONS

A: textual Glon, compiled by the unchanged B3 compiler.
B: semantically tagged 32-bit words, explicit roles; B4 decoder/emitter.
C: direct machine-oriented 32-bit words with labels/relocation; B4 assembler.

All three generate IDENTICAL code cells and instructions for every task.

  A text parse+compile: median 68.79 us across tasks (task medians 52.89-88.60)
  B tagged decode+emit: median  0.30 us across tasks (0.26-0.43)
  C direct assembly:    median  0.28 us across tasks (0.23-0.46)

execution (identical code, so representation differences are noise):
  fib ~288 us, sum ~34 us, max3 ~0.10 us, fact ~0.50 us, diff ~0.07 us,
  nested ~0.04 us, forward ~0.03 us.

The B3 API exposes only combined parse+compile; A cannot be split into
parse-only and codegen-only without changing B3. B and C are single-pass
decode+emit / assemble. The numbers are comparable source-processing totals.
The B/C fixtures were prepared by tools/gen_fixtures.py; artifact authoring and
lowering cost is not included. C's assembler does no lowering; that work is in
the artifact/generator, so its small size is not a whole-system simplicity win.

ERROR DETECTION AND DIAGNOSTICS

A: B3 parser rejects syntax, unknown names, arity/parameter errors, unsupported
   forms.
B: rejects bad magic/truncated words, unknown roles, duplicate function ids,
   out-of-range parameters, undefined calls and call-arity mismatches.
C: rejects bad magic/truncation, unknown operations, duplicate labels,
   undefined/missing entry and undefined labels. It cannot detect stack
   imbalance, function arity mismatches or language-level errors.

LLM GENERATION AND REPAIR

Not performed: no LLM was available. The harness is in generation/ with task
specs and three format prompts, including a repair loop. No model-token or
productivity claim is made.

LIMITATIONS

- Restricted integer subset; no closures, dynamic binding, escape laws,
  managed values/GC, errors/judge, locals or loader integration.
- A uses the full B3 compiler, which also contains convention-B support; its
  size overstates a convention-A-only text compiler.
- Wall-clock source processing for B/C is near timer resolution; the
  order-of-magnitude gap from A is robust, individual sub-microsecond values
  are not.
- B/C source widths are fixed four bytes; no variable-length/compression
  experiment.
- C cannot validate arity or stack behavior.
- No LLM trial was run; no ease-of-generation claim.
- Execution code is identical; B4 measures representation front-ends.
