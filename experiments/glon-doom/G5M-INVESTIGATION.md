# Glon AvP G5m — playable OpenGL and replacement creature

Branch: `glon-avp-g5m`  
Base: `e11649f6e706a486f117c5420e4a49a468c17cf8` (G5l)  
Target: WSLg, AMD Ryzen 5 7535U / AMD Radeon, Mesa OpenGL 4.2 compatibility,
SDL2, GCC 11.4.0 `-std=c17 -O2`.

Verified GPU: `D3D12 (AMD Radeon(TM) Graphics)`,
vendor `Microsoft Corporation`, Mesa 23.2.1-1ubuntu3.1~22.04.4.

## 1. Interactive loop integration

`interactive_gl()` now runs the same fixed-timestep loop as the CPU game:

- polls SDL events and `SDL_GetKeyboardState`;
- maps W/S/A/D, Left/Right, E, Esc exactly as the CPU renderer;
- calls the authoritative Glon `tick` block at 60 Hz;
- reads the same player/door/Alien/object/light status;
- renders through `gl_scene()` and swaps the GL window;
- preserves collision, door operation, Alien pursuit, object collision and
  motion-tracker state because none of that moved into C.

The normal launch now uses OpenGL when available:

```sh
./build/doom                       # G5m, OpenGL 640x400, objects enabled
./build/doom --renderer gl         # explicit GL
./build/doom --renderer cpu        # CPU reference/fallback
./build/doom --gl-bench 120 640 400 objects
./build/doom --gl-demo 640 400 objects
./build/doom --gl-shots DIR 640 400 objects
```

Startup prints G5m, backend, framebuffer, GPU identity and interactive state.
Window titles are G5m CPU/OpenGL. If GL context creation fails, the default
path prints a diagnostic and falls back to the CPU renderer.

R retains the CPU textured/simple debug toggle. In GL it reports that the debug
toggle is not applicable.

## 2. Sprite orientation diagnosis

The G5l upside-down Alien was caused by OpenGL's texture-origin convention:
source PNG/array row 0 is the top, while GL texture V=0 is the bottom. G5l
uploaded rows in source order and then mapped V=0 to the billboard bottom, so
the sprite was inverted.

G5m fixes the cause in `gl_upload()` by reversing source rows during upload.
The same upload is used for walls, floor, ceiling, door, props and all Alien
frames. A dedicated asymmetric red/blue TOP/BOTTOM diagnostic is rendered by
`--gl-orient DIR 640 400`; `/tmp/g5m-orientation.png` shows TOP above BOTTOM.
The new Alien (cranial dome at top, feet/claws at bottom) is upright in the GL
corridor and cover screenshots. Props and the door are also upright.

## 3. Replacement creature

The new creature is generated by `tools/gen_alien_g5m.py`, an original layered
procedural artwork pipeline (not contact-sheet/copyrighted extraction):

- 128×192 RGBA frames, 6 states: idle, walk1, walk2, attack, side, death;
- long smooth eyeless cranial dome, recessed jaw/teeth;
- near-black charcoal/gunmetal body, ribbed torso, narrow waist;
- long segmented arms/legs, elongated claws, digitigrade stance, segmented tail;
- restrained silver-grey highlights, no bright green body/red glowing eyes.

Assets: `sprites/aliens_g5m/*.png`, generated `alien_sprites_g5m.h`.
Per-frame transparent corners, alpha edges and non-empty opaque pixels are
checked by `tests/check_aliens.py` at the new dimensions.

Quality sheet: `/tmp/g5m-quality-sheet.png` shows native 128×192, typical
96×144, small 32×48 and diagnostic 256×384. The silhouette remains readable at
small size. Contact: `/tmp/g5m-creature-contact.png`.

Death is supplied as an asset but is not wired to gameplay because G5m has no
damage/death state; no AI or damage was added.

## 4. Actual gameplay verification

Automated GUI input through WSLg is unreliable for all keys, but a real W
key-down held via Windows `keybd_event` moved the authoritative Glon player:

```
G5m GL frame=240 player=744,320 angle=0 door=0/1 ...
```

This verifies that the normal no-argument GL loop is receiving keyboard state
and feeding the same Glon simulation path. Door/arrow injection from the
external PowerShell helper was not reliable enough to claim a complete
automated playthrough. Exact manual procedure:

1. `./build/doom`
2. Hold W to approach the door.
3. Press E; watch the door open.
4. Hold W through the doorway.
5. Press Left/Right to turn and A/D to strafe.
6. Continue to the crate/objects and observe Alien cover.
7. Press Esc.

## 5. Performance

Same GPU, 120 frames, objects/Alien active:

| Configuration | FPS | Sim | Submit+finish | Total |
|---|---:|---:|---:|---:|
| G5k CPU 320×200 | 27.5 | 5.1 ms | — | 36.4 ms |
| G5m GL 320×200 | 45.7 | 17.1 ms | 2.27 ms | 21.87 ms |
| G5m GL 640×400 (median of 3) | 45.8 | 14.9–17.0 ms | 2.31–2.41 ms | 20.2–22.1 ms |
| G5m GL 960×600 | 41.5 | 18.1 ms | 2.63 ms | 24.11 ms |

G5l measured ~60 FPS at 640×400 with the smaller sprite set; G5m's larger
128×192 artwork/host changes correlate with a lower 45–50 FPS range. It remains
well above the CPU reference and responsive. `glFinish` is included; this is
completed-frame time, not command submission alone. Remaining CPU cost is
Glon simulation/status/object projection, not GPU fill.

## 7. Ceiling lighting and scene consistency

Illuminated ceiling texture/panels and four localized emissive strips remain.
Glon increments `light-phase`; the renderer applies a subtle localized pulse.
Door, object and Alien depth testing remains GPU-side.

Static wall geometry is still duplicated as a renderer-side ABI copy (ten wall
records, door, planes). Dynamic camera/door/object/Alien/light data comes from
Glon. This duplication is explicit; a compact versioned Glon scene block is the
next architecture cleanup. No per-frame graphics command stream is generated by
S1.

## 8. Sound interface proposal

No audio implemented. Proposed SDL event records from Glon:
`footstep`, `door-start`, `door-stop`, `ambient-machine`, `tracker-beep`,
`alien-move`, `alien-hiss`. Glon emits events; the host selects/mixes short
samples. No sound engine in Glon or renderer.

## 9. Tests

`make test` passes in the isolated worktree: all G5a–G5l texture/Alien/
projection/stationary/object/raw-wall/frozen checks, plus the updated 128×192
creature asset checks. `--gl-bench` smoke succeeds on the verified device.

Limitations:

- External keyboard automation could not reliably exercise E/arrows; W movement
  was verified. Manual procedure above is required for full interactive proof.
- Static geometry remains duplicated in the renderer ABI.
- Fixed-function OpenGL 2.1 compatibility, no shaders/mipmaps.
- Death art not wired because no death state.
- No audio.

## 10. Recommendation

G5m is a playable GL milestone if manually verified with the procedure above.
Next: move static scene data into a compact, versioned Glon scene block; make GL
the default with CPU fallback; add the event-driven sound bridge. The creature
is a procedural original design, substantially closer to a biomechanical horror
silhouette than the cartoon placeholder, but it remains stylized rather than a
photoreal Alien.
