# Glon AvP G5i — a proper Alien

Branch: `glon-avp-g5i`
Base: `de1089b97d0234bacbf7db37fe4638f76b6911da` (G5h)
Configuration: native 64K reference machine, WSL2, AMD Ryzen 5 7535U,
GCC 11.4.0, `-std=c17 -O2`, SDL2. No frozen-S1, primitive, resolution,
wall-renderer, environmental-art or gameplay change.

## 1. Alien sprite source and assets

**Reference limitation:** the requested `sprites/sprites.png` is not present in
this worktree. `sprites/` contains only
`Glon_AvP_Industrial_Texture_Set.png` (the G5d environment contact sheet), and
it contains no Alien art. No Alien could be cleanly extracted from it, so no
contaminated crops or labels were used.

The Alien assets are original 64×128 transparent pixel-art frames generated by
`tools/gen_alien_sprites.py` in the environment's restrained charcoal/green
palette:

| Asset | File | Purpose |
|---|---|---|
| idle | `sprites/aliens/idle.png` | front idle |
| walk A | `sprites/aliens/walk1.png` | approach, left lead |
| walk B | `sprites/aliens/walk2.png` | approach, right lead |
| attack | `sprites/aliens/attack.png` | raised claws, open jaw |
| side | `sprites/aliens/side.png` | off-axis/profile option |

`alien_sprites.h` is generated from those PNGs as `0xAARRGGBB` arrays. The
64×128 size matches the Glon sprite rectangle, whose drawn width is half its
height; using 96×128 would have been horizontally squeezed.

Asset validation (also `make test`):

- 64×128 RGBA;
- four transparent corners;
- 1,914–2,085 fully opaque pixels per frame;
- 4,569–4,689 fully transparent pixels per frame;
- PNG total 49,111 bytes; compiled frame arrays 163,840 bytes;
- no labels, background rectangles or contact-sheet borders.

The Alien has an elongated biomechanical head, slit eyes, mouth/teeth, ribbed
segmented torso, clawed articulated limbs and a long tail. The attack frame
raises the arms and opens the mouth; both walking frames alternate limb/tail
poses.

## 2. Rendering and animation

Glon still owns the Alien world position, state, line-of-sight/door occlusion
and projected `left/right/top/bot` rectangle. The host only decodes/samples the
prepared sprite.

Rendering:

- transparent alpha test and alpha blending;
- nearest-neighbour sampling for the retro sprite, preserving hard pixel edges;
- perspective size from the existing Glon rectangle, with no host-side world
  geometry;
- clamped near-plane/screen bounds;
- distance shading: 112% close, 100% normal, 86% far, 72% very far;
- stable world anchoring via the Glon rectangle;
- no background rectangle and no green polygon fallback;
- wall/door visibility remains governed by `Status.visible` from Glon.

Animation is driven by `sim_tick`, incremented once per simulation tick, not by
display frame rate:

- state 0: idle (profile only for strongly off-axis tracker positions);
- state 1: walk frames alternate every 8 simulation ticks;
- state 2: attack frame.

The new self-test checks idle/walk-A/walk-B/attack frame selection, transparent
corners and non-empty drawn pixels. Existing movement, collision, door and
tracker behavior is unchanged.

Rendered sprite cost when visible and close: **0.10–0.11 ms/frame**.

## 4. Wall pixelation / “Tetris wall” diagnosis

Controlled comparisons, same geometry and material assignments:

1. **Existing nearest-neighbour** framebuffer upscale: 320×200 → 960×600.
   `/tmp/g5i-room-nearest.png`
2. **Bilinear scaling of the completed framebuffer** (Python controlled
   comparison and optional SDL `--filter linear`): `/tmp/g5i-room-bilinear.png`,
   `/tmp/g5i-linear.png`.
3. **Checker/grid diagnostic texture** on the existing wall geometry/material
   assignments: `--checker`; contact `/tmp/g5i-wall-diag.png`.

Findings:

- The checker does **not** reveal hidden gaps between the 2-pixel wall strips.
  Wall texture coordinates are continuous within each wall; material changes at
  wall boundaries are intentional.
- The dominant blockiness is a presentation/representation combination:
  320×200 internal resolution, 3× nearest scaling, 160 projection columns at
  2 framebuffer pixels each, 64×64 textures repeated every 256 world units, and
  four discrete shading levels.
- Bilinear scaling softens the 3× staircase but also blurs texel detail. It does
  not remove the repeated 64×64 tile pattern.
- The environment still uses its original G5d artwork; no environmental texture
  or material assignment was replaced in G5i.

Recommendation: keep nearest-neighbour as the default retro presentation, with
`--filter linear` available as an explicit final-framebuffer option. The
smallest real environmental improvement for G5j is a higher internal
resolution/texel-density or tiling review, not a global blur that hides the
repetition. No UV seam error was found to conceal.

## 5. Performance and memory

G5h raw-wall baseline was 19.5–20.3 FPS textured. G5i keeps the same raw wall
path and Glon operation counts. Absolute wall time varies with host binary
layout (documented in G5g), so the comparison below is evidence of no material
regression, not a sprite speedup claim.

| Textured, 3 × 120 frames | Median |
|---|---:|
| FPS | **21.8** (21.5–21.9) |
| Wall | 15.54 ms |
| Texrow | 20.24 ms |
| Raster | 0.47 ms |
| Sprite (not visible in start pose) | 0.00 ms |
| Total | 45.78 ms |

Close/visible Alien (3 × 60 frames):

| Metric | Median |
|---|---:|
| FPS | **21.1** (21.0–21.3) |
| Wall | 15.98 ms |
| Sprite | **0.10 ms** |
| Total | 47.30 ms |

Glon path unchanged:

- wall S1 operations/frame: **4,555,404**
- wall HOST calls/frame: **846,833**
- managed heap/frontier: **33,472**
- GC: **0**
- loader after host blocks: **14,322 used / 478 free**
- code cursor / limit: **14,828 / 16,128**

Native sprite memory is **163,840 bytes** of compiled frames plus **49,111
bytes** of PNG source; it does not consume Glon loader or managed cells.

## 8. Recommendation for G5j

Keep the Alien renderer. Investigate environmental presentation separately:
higher internal resolution or texel/tiling review, with the checker diagnostic
retained. Do not replace the G5d artwork or add blur to hide texture repetition.
If the final upscale is changed, measure it as a presentation option rather than
altering wall geometry/UVs.

`glon-avp-g5i`; the final commit hash is reported in the delivery message.
