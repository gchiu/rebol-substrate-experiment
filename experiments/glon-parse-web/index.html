Glon experiment

Glon Parse

Rebol 2-style PARSE on the original seven-primitive S1 execution core.

Glon is an experimental compact execution language for AI-generated software. This page runs the existing Glon PARSE engine—the same rule interpreter tested against a genuine REBOL/Core 2.7.8 oracle—in WebAssembly on the frozen S1-7 runtime.

The parser, search, repetition, character-set matching and capture logic run in Glon. JavaScript only loads the runtime, sends the source/rule text, and displays the Glon output.

Editable rules use the existing encoded Glon representation. The generated driver is limited to 16 KiB by the runtime source buffer; inputs are limited to 2,000 UTF-8 bytes.

Result

Encoded rule representation

This is the Stage 1–2E Glon rule data, not text Rebol syntax. Rules are ordinary Glon data built with reduce; a literal Glon block is code, so string-containing rules use nested reduce.

DataMeaning
"literal"literal string; case-insensitive by default
[ rule … ]sequence; 0 separates ordered alternatives
[ 1 rule ], [ 2 rule ], [ 3 rule ]some, any, opt
[ 4 ], [ 5 "target" ], [ 6 "target" ], [ 7 ]skip, to, thru, end
[ 8 descriptor ]charset; descriptor = byte pairs lo,hi
[ 20 n rule ], [ 21 min max rule ]exact / bounded repetition
[ 9 "name" rule ]copy capture; names are strings in this page
'nonezero-length success, no consumption
'namenamed rule from the flat registry

set, ahead and not are not R2 string-parse capabilities and are not offered here. There is no textual Rebol rule reader, block parsing or arbitrary action execution.

Execution path

Core
Frozen S1-7: LIT DUP DROP @ ! 0BRANCH HOST. Not S1-12.
Runtime
Standard glon.wasm (seven-primitive shop runtime) built from the current runtime sources.
Parser
The existing parse.glon from experiments/glon-parse-r2/; captures are displayed after the parse. No host parser or precomputed results.
Verification
Repository baseline: 151/151 Glon checks and 127 Rebol 2 oracle probes. Those are repository results, not tests performed by each click.
