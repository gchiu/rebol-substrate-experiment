SEMANTICS FINDING

Definitions-only Glon is a valid loaded module in production Glon:
`f: func [x] [ x ]` loaded by ./glon exits 0 and returns #[func].
The B5/B6 benchmark compiler (`b3_compile`) is a standalone-entry compiler: it
requires a top-level expression, emits it as the entry and HALTs. It has no
module mode. The benchmark tasks need that invocation to obtain a result.
`missing_top_level` in B6 was therefore a benchmark submission-contract issue,
not a Glon language requirement.

PROMPT DIFF A -> E

A is the B6 textual prompt unchanged. E adds exactly one paragraph:

  The benchmark submission must include the specified top-level invocation
  after the function definitions. Definitions alone are a valid Glon module,
  but this benchmark executes the final top-level expression to obtain its
  result; a definitions-only artifact does not produce a test result.

No syntax, semantic role, example or reference code was added. Exact diff is in
generation/prompts/DIFF.md.

ANALYSIS ANSWERS

1. Does clarification reduce missing_top_level? Yes: 8 -> 0 first-attempt
   missing-entry failures.
2. Does it improve first-attempt correctness? Yes in this pilot: 10/24 -> 17/24
   (seed 1 4->10, seed 2 6->7).
3. Does it reduce total LLM tokens/cost? No overall: E used 120,249 tokens /
   $0.065439 vs A 81,193 / $0.042130. Seed 1 was roughly neutral
   (38,781/$0.020400 vs 37,471/$0.019369); seed 2 was worse because of the
   choose outlier (81,468/$0.045039 vs 43,722/$0.022760).
4. Any new failure modes? No new final or timeout failure. E shifted first
   failures from missing entry to control-flow (6 vs 4) and one unknown
   reference; no missing-entry failures.
5. Effects consistent across tasks/seeds? First-attempt improvement appears in
   both seeds (4->10, 6->7), but magnitude and cost are not consistent; one
   seed-2 task dominates total cost. Mixed overall.
6. Is the rule language or benchmark? Benchmark submission/execution contract,
   not a Glon language rule. Definitions-only is a valid module.

HYPOTHESIS

Partially supported:
- Strongly supported for the specific failure: the clarification removes
  missing_top_level and raises first-attempt success.
- Not supported as a general cost reduction: total tokens/cost rose in the
  two-seed aggregate, driven by increased model reasoning and one outlier.
- Final correctness remained 24/24 in both conditions; E needed fewer attempts
  (36 vs 41) and repairs (12 vs 17), but at higher aggregate token cost.

B's historical high first-attempt rate remains above E, but B5's controlled
documentation fix showed that documentation can move B from 0/12 to 11/12;
representation versus documentation is still not fully separated, and B was
not rerun in B7.

LIMITATIONS

- Two seeds, 24 trials per condition, one model/variant, 12 small tasks.
- B and C are historical/not rerun; no controlled A/B claim.
- Results are mixed and not statistically established.
- The completion rule is benchmark-specific; changing language semantics was
  neither needed nor done.
- Validator feedback is shared by A/E; the prompt is the only difference.
- No reference implementation was exposed; isolation protocol was preserved.
