ADAPTER DEFECTS (separate from model failures)

1. Initial suite invocation used the wrong working directory for
   generation/run_trial.sh, which resolves ../tasks and prompts relative to
   generation/. It produced no model calls. Fixed in run_opencode_suite.py by
   running run_trial.sh from generation/.

   reasoning. It caused zero-token calls with 170-180 s process time. This is
   an adapter/infrastructure interruption, not a model-generation outcome.
   The committed adapter default is now B5_OPENCODE_TIMEOUT=900.

FAILURE PATTERNS (raw attempt diagnostics)

A: first-attempt failures were textual/syntax or missing top-level expression:
   "no top-level expression", malformed either blocks, unexpected ']'.
   All were repaired; A needed one repair for 9 of 12 tasks, three succeeded
   first, and quad needed three repairs.
B: all 12 first attempts failed at token 1 with "bad function id". The B prompt
   encodes FUNC operand as id<<8|arity but did not state that function ids
   start at 1; the model repeatedly used id 0. Repairs fixed this. Across all
   attempts there was one incorrect-semantics and one stack-category failure.
   B diagnostics are token-index based and less natural, but all 12 tasks
   eventually passed.
C: 38 of 48 attempts were invalid representation/encoding and 10 were
   incorrect semantics; 11/12 trials were timeout-affected. The one trial
   without timeouts (quad) produced a wrong result. C diagnostics are
   mechanical (label id, unknown operation, bad file size) and do not
   consistently guide repair to the ABI/stack problem.

INTERPRETATION / UNCERTAINTY

A completed all tasks at the lowest measured model cost among valid rows.
B completed all tasks but required more repairs and about 3.2x A's cost and
3.1x A's tokens. B's first-attempt rate is confounded by a systematic prompt
ambiguity about function ids, not by semantic difficulty alone.
C is unanswered: the 180 s adapter cap, not the model, invalidated most C
trials. Do not report C as inferior or superior from this run.
Sample size is 12 tasks per representation; this is a pilot, not proof.
No reference implementation was exposed: prompts contained only task specs and
representation docs, the agent had all tools disabled, and each invocation used
a fresh temporary project. Raw JSON events, artifacts, diagnostics, sessions,
tokens and provider costs are preserved under trials/.

INTERPRETATION

Among completed representations, A original used the least total model effort
(tokens, cost and process time). B corrected is much cheaper than B original
and much more reliable on first attempt; the improvement is attributable to the
documented identifier rules, not a binary/decoder change. C remains unable to
produce a final correct program in the full 12-task follow-up even with the
900 s timeout, despite one smoke success; its effort was about 14x A's cost
with zero final successes.

These are 12-task pilot data, not statistically established superiority. C's
smoke/full difference and the one B max_neg repair show model variability.
No new reference implementation was exposed; the follow-up used the same
tool-free, fresh-session isolation protocol.
