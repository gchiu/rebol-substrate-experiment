Glon

Glon is a compact, reliable execution substrate designed primarily for LLM-generated software, with a Rebol-family language and heritage.

It runs interactively in WebAssembly, right in this browser. Code is made of blocks, words and values; functions are lexically bound closures; programs can run as cooperative tasks; and failures are first-class SIN! values that you raise and judge.

What Glon is

Small enough to inspect

Ordinary programs stay in Glon. The substrate beneath them is a frozen 65,536-cell machine with seven primitives: LIT DUP DROP @ ! 0BRANCH HOST. Higher-level machinery is built above it rather than added as new machine features.

Reliable for generated code

The language has a written Alpha contract, a formal reader grammar, explicit resource limits and tests for closures, failures, memory and the escape law. That makes generated programs easier to bound, check and explain.

The host is not the language

Glon decides; the host moves bytes; the browser presents them. Browser, native and WebAssembly hosts supply I/O and presentation, not application routing or domain semantics.

Glon also keeps a Rebol-family shape: blocks are data, words are looked up in lexical contexts, calls are prefix and fixed-arity, and functions are closures. It deliberately differs too: no infix operators or parentheses, no true/false words, immutable byte strings, recursion instead of loop words, and first-class SIN! failures.

Execution model and guarantees

Glon evaluates a flat stream of forms. A word looks up a value in the current lexical context; a callable consumes its fixed number of following expressions; a block is data until do, values, reduce, a function body or another control form evaluates it.

Values and binding

Every value is one tagged cell. Contexts form a lexical parent chain. A set-word updates the nearest existing binding, otherwise it creates a local in the current call. Closures capture the actual context and remain portable after their creator returns.

Failures are values

A SIN! is inert data until raised. raise unwinds to the nearest judge in the same task. Machine failures — exhausted memory, stacks or contexts — are fail-stops, not catchable SIN! values.

Written guarantees

The Alpha laws, formal grammar, escape law and native/WASM test suites are part of the project. The generated grammar reference separates verified reader behaviour from unresolved semantics instead of guessing.

;; => 42

What Glon has today

  • Blocks and words. A block is data until something evaluates it.
  • Lexical binding and closures. A function keeps the context it was made in; a block that depends on a call may not escape that call.
  • Cooperative tasks. spawn, yield and run-tasks interleave work deterministically.
  • SIN!, raise and judge. Creating a sin is harmless. Raising it causes trouble. Judgment permits execution to continue.
  • Executable laws. The language is developed against written laws and a native test suite, and the browser examples are tested too.
  • Real programs. The traffic simulator runs IDM, Newell, OVM/FVDM and NaSch models in Glon, in the browser.

Glon is a place for gloriously hacking both the code and the language. It is an experiment: expect sharp edges, and expect it to change.
