Glon HTTPS Server

A programmable HTTPS application server in under 300 KiB.

Glon combines a compact interpreter with HTTPS transport, application routing, dynamic HTML generation, JSON processing, form handling and persistent application state.

CivetWeb and OpenSSL provide the native HTTP and TLS infrastructure. Application behaviour is implemented in Glon.

The smallest verified HTTPS application requires six lines and 125 bytes of application source.

Network

Glon owns routing, validation, response content and status selection, HTML/JSON generation, JSON encoding/decoding and persistence logic. CivetWeb and OpenSSL provide sockets, HTTP parsing and TLS; they contain no application routes or membership fields. The 64K constrained profile and the large profile share the same frozen execution semantics; only capacity and address layout differ.

The four verified HTTPS examples

These are actual sources executed locally during release verification. The outputs below are recorded transcripts, not live server responses. Each example is also downloadable.

Example 1 — Hello World — 6 lines / 125 bytes

Dependencies. Constrained HTTPS build. No application libraries beyond the built-in HTTP vocabulary.

Source

[
hello: func [request] [
    http/respond request 200 "text/plain; charset=utf-8" "Hello World"
]
http/listen 8443 :hello
]

Build and run

make glon MODULES=http
./glon --http-cert tests/https-g1/.cert/server.pem 1-hello.glon

Curl test

curl -k https://127.0.0.1:8443/

Verified output

HTTP/1.1 200 OK
Content-Type: text/plain; charset=utf-8
Content-Length: 11

Hello World

Example 3 — HTML and JSON routing — 23 lines / 609 bytes

Dependencies. Constrained HTTPS build. Uses `s/+`, `mk-string`, `str-eq` from the shipped libraries.

Source

[
q: mk-string reduce [ 34 ]
json-body: s/+ "{" q
json-body: s/+ json-body "ok"
json-body: s/+ json-body q
json-body: s/+ json-body ":true}"

html-body: "<!doctype html><html><body><h1>HTML route</h1></body></html>"

home: func [request] [
    path: http/path request
    either str-eq path "/" [
        http/respond request 200 "text/html; charset=utf-8" html-body
    ] [
        either str-eq path "/api" [
            http/respond request 200 "application/json" json-body
        ] [
            http/respond request 404 "text/plain; charset=utf-8" "not found"
        ]
    ]
]
http/listen 8443 :home
]

Build and run

make glon MODULES=http
./glon --http-cert tests/https-g1/.cert/server.pem 3-routes.glon

Curl test

curl -k https://127.0.0.1:8443/
curl -k https://127.0.0.1:8443/api
curl -k -i https://127.0.0.1:8443/missing

Verified output

GET /        -> 200 text/html; charset=utf-8
GET /api     -> 200 application/json
                {"ok":true}
GET /missing -> 404 text/plain; charset=utf-8

Example 4 — POST and JSON processing — 29 lines / 1,038 bytes

Dependencies. Large memory profile plus `modules/json.glon` (782 lines / 26,752 bytes). The JSON module requires the large loader.

Source

[
home: func [request] [
    method: http/method request
    either str-eq method "POST" [
        body: http/body request
        decoded: judge [ json/decode body ]
        either sin? decoded [
            http/respond request 400 "text/plain; charset=utf-8" "malformed JSON"
        ] [
            either json/object? decoded [
                name: json/object-get decoded "name"
                either json/string? name [
                    pair: reduce [ "hello" name ]
                    pairs: reduce [ pair none ]
                    out: json/encode json/object pairs
                    http/respond request 200 "application/json" out
                ] [
                    http/respond request 422 "text/plain; charset=utf-8" "name must be a string"
                ]
            ] [
                http/respond request 400 "text/plain; charset=utf-8" "JSON body must be an object"
            ]
        ]
    ] [
        http/respond request 405 "text/plain; charset=utf-8" "POST only"
    ]
]
http/listen 8443 :home
]

Build and run

make glon MODULES=http MEM_PROFILE=large MEM_LOADER_CELLS=500000
./glon --http-cert tests/https-g1/.cert/server.pem modules/json.glon 4-post-json.glon

Curl test

curl -k -X POST -H 'Content-Type: application/json' --data '{"name":"Ada"}' https://127.0.0.1:8443/
curl -k -i -X POST -H 'Content-Type: application/json' --data '{' https://127.0.0.1:8443/

Verified output

POST {"name":"Ada"} -> 200 application/json
                       {"hello":"Ada"}
POST {             -> 400 text/plain; charset=utf-8
                       malformed JSON

Download 4-post-json.glon

Advanced experimental application — membership register

Experimental, synthetic data only. The G3A membership register demonstrates listing, viewing, adding, editing, HTML forms, a JSON API, validation, duplicate detection, pagination and NDJSON persistence. It is not exposed as a public internet service in this release.

Source modules:

  • server.glon — entry point, routes, HTML/JSON
  • reg.glon — register, validation, hash/overflow
  • slots.glon — generated 160 × 64 slot table
  • persist.glon — NDJSON append log and replay
  • web.glon — form decoding and HTML escaping
  • json.glon — general JSON vocabulary

Launch (Linux)

make glon MODULES=file,http MEM_PROFILE=large MEM_LOADER_CELLS=500000
tests/https-g1/make-cert.sh
./glon --http-cert tests/https-g1/.cert/server.pem \
    --allow-file-read --allow-file-write --io-root . \
    glon-lib/web.glon glon-lib/json.glon \
    examples/https-g3a/slots.glon examples/https-g3a/reg.glon \
    examples/https-g3a/persist.glon examples/https-g3a/server.glon

Routes

GET  /                     paginated HTML member list
GET  /add                  add-member HTML form
GET  /members/<id>         member detail / edit form
POST /                     add (form)
POST /members/<id>         update (form or PUT)
GET  /api/members?page=N   JSON page
POST /api/members          add (JSON)
GET  /status               JSON status and persistence state

Measured limits: the 200-record restart acceptance passed. The 1,000-record restore took 450.143 s; the 10,000-record restore failed with return-stack exhaustion. No 100,000-request endurance claim is made. See the release documentation for full measurements and limitations.

Build and certificate instructions

Linux dependencies: build-essential, libssl-dev, openssl. Windows builds in this preview are native x86-64 executables; the constrained HTTPS and large HTTPS/JSON packages include the required OpenSSL DLLs. The Windows file-enabled membership package is not included because the current file module has no Win32 backend (see the release manifest).

# Linux
make glon MODULES=http
tests/https-g1/make-cert.sh
./glon --http-cert tests/https-g1/.cert/server.pem 1-hello.glon
curl -k https://127.0.0.1:8443/

# Windows PowerShell (HTTPS package)
.\make-cert.ps1
.\glon.exe --http-cert .\server.pem 1-hello.glon
curl.exe -k https://127.0.0.1:8443/

Honest status

Verified: native interpreter; constrained and large profiles; M1 multitasking on the large profile; HTTPS transport; GET/POST/PUT; HTML responses; forms; JSON encode/decode; file-backed persistence on Linux; NDJSON restart; four verified HTTPS examples.

Not claimed: concurrent Glon request handlers; production readiness; long-term server reliability; authentication, authorisation or CSRF protection; 10,000-record restore; 100,000-request endurance; Windows file-enabled membership persistence; runtime-selectable memory.

The next networking milestone is a UniServe-inspired asynchronous, multiprotocol substrate. Those capabilities are proposals, not implemented features. UniServe has not been recreated in Glon.
